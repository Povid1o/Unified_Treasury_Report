# Отчёт по портфелям

Код: [reports/portfolio_report/](../reports/portfolio_report/) (`etl.py` —
разбор и CSV, `market.py` — история RUONIA/RGBI/RWA, `workbook.py` — xlsx с
комментариями). Команда: `python console.py portfolio-report`.

## Источник

**1. Та же выгрузка «Позиция за период», что у «Динамики портфелей»**, одна,
**с начала года по T-1** (предыдущий рабочий день; праздники не учитываются):
`Позиция за период  01.01.ГГГГ  -  ДД.ММ.ГГГГ   - SECURITIES.xlsx`. Колонки
«(нач.)» в ней — на 01.01, «(кон.)» — на T-1. Разбор файла — общий с
«Динамикой» (лист с колонкой «Тип актива», строки `Позиция: <КОД>`).

Где ищется, по порядку: своя папка `portfolio_report_dir` (папки-даты
`ГГГГ-ММ-ДД`), папка «Динамики портфелей», загрузки. Найденное не у себя
кладётся в свою папку. Из загрузок выгрузка «01.01 – дата» ложится сразу в
обе папки — свою и «Динамики»; в папку-дату «Динамики» — только если там ещё
нет среза на ту же дату (например, выгрузки за один день). Из загрузок файл
убирается, только если лёг хотя бы в одну папку.

Принимается **только** выгрузка «01.01 – дата» того же года — и при
автоподборе, и через `--input`. Выгрузка за один день не годится (изменение
Open QTY в ней всегда ноль), выгрузка с другой начальной даты — тоже
(изменение было бы не с начала года). Если на дату лежат несколько видов,
берётся выгрузка с начала года.

| Колонка выгрузки | Показатель | Как сворачивается в портфель |
|---|---|---|
| Тип актива | код портфеля из `Позиция: <КОД>` | — |
| Open QTY (кон.) | `Open QTY` — на T-1 | из строки портфеля; пусто — сумма по бумагам |
| Open QTY (нач.) | `Open QTY на начало года` — на 01.01 | из строки портфеля; пусто — сумма по бумагам |
| — | `Изменение Open QTY` | `Open QTY` − `Open QTY на начало года` |
| Чистая стоимость позиции (кон.) | `Чистая стоимость` (балансовая стоимость) | из строки портфеля; пусто — сумма по бумагам |
| Total Full PL with Funding | `Total Full PL with Funding` — за период, то есть с начала года | из строки портфеля; пусто — сумма по бумагам |
| DV01 (кон.) | `DV01` | **сумма** по бумагам портфеля; строка портфеля не используется |
| Yield (кон.) | `Yield` | **средневзвешенная** по бумагам портфеля, вес — «Чистая стоимость позиции (кон.)» бумаги; строка портфеля не используется |

Бумаги портфеля — все строки под `Позиция: <КОД>` до следующей такой строки.

Тип портфеля — по коду, по тем же правилам разметки, что у «Динамики»
(`portfolio_types.json`, правила и исключения из настроек).

**2. xlsx-витрина последнего выпуска** (с датой **не позже** T-1) — комментарии.

**3. RUONIA, RGBI, RWA** — вводятся руками при запуске (или `--ruonia`,
`--rgbi`, `--rwa`). Каждый запуск дописывает их в файл истории
`market_history.csv` (бэкап). Начальная история — `seed/market_history_seed.csv`.

**4. Дополнительные портфели** — портфели, которых нет в выгрузке. Список —
Excel-файл `additional_portfolios.xlsx`, общий с «Динамикой портфелей»
(код, тип, балансовая стоимость в млн RUB, Open QTY в штуках, комментарий). P&L с начала
года по ним вводится при запуске в млн RUB (или `--manual-pl "КОД=число"`);
не введён — берётся прошлый. Каждый запуск дописывает его в
`manual_pl_history.csv` (бэкап).

| Показатель | Откуда у дополнительного портфеля |
|---|---|
| `Open QTY`, `Open QTY на начало года` | Open QTY из файла (один на любую дату); пусто — строк нет |
| `Изменение Open QTY` | 0 |
| `Чистая стоимость` | балансовая стоимость из файла, в рублях |
| `Total Full PL with Funding` | введённый при запуске P&L с начала года, в рублях |
| `DV01`, `Yield` | не пишутся |
| `Комментарий` | колонка «Комментарий в портфелях» файла (витрину перебивает) |

Код, который есть в выгрузке, из файла не берётся. В CSV дополнительный
портфель ничем не отличается от остальных: тот же `axis_1` (тип) и `axis_2`
(код).

## Выходные файлы

- `otchet_po_portfelyam_<T-1>.csv` — **для BI**. Разделитель `,`, UTF-8 с BOM.
- `otchet_po_portfelyam_<T-1>.xlsx` — витрина для людей: строка на портфель и
  жёлтая колонка «Комментарий». **В BI не грузится.**
- `market_history.csv` — бэкап истории рынка (колонки `date, RUONIA, RGBI,
  RWA`). **В BI не грузится** — история приходит в BI через CSV выпусков.

## Таблица в базе (CSV)

| Колонка | Тип | Что в ней |
|---|---|---|
| `id` | int | номер строки в файле, с 0 — не ключ |
| `date_` | date | дата позиций (T-1); у RUONIA/RGBI/RWA — дата значения (см. ниже) |
| `axis_0` | text | всегда `Портфели` |
| `axis_1` | text | тип портфеля (`AFS`, `HTM`, `HTM_KUAP`, `TSS`) или `Рынок` |
| `axis_2` | text | код портфеля; у строк `Рынок` пусто |
| `axis_3` | text | показатель (таблица ниже) |
| `axis_4` | text | единица |
| `value` | decimal / пусто | число; у комментария пусто |
| `text_value` | text / пусто | текст комментария; у числовых строк пусто |
| `nversionid` | text | пусто |

Если будет доделан флаг «Портфели Казны» (настройка
`portfolio_report_own_portfolios`), добавится колонка `indicators` (0/1) —
её стоит сразу заложить в таблицу как int с NULL.

| `axis_1` | `axis_3` | `axis_4` по умолчанию | Что |
|---|---|---|---|
| тип | `Open QTY` | шт | количество бумаг на T-1 |
| тип | `Open QTY на начало года` | шт | количество бумаг на 01.01 |
| тип | `Изменение Open QTY` | шт | изменение с начала года: `Open QTY` − `Open QTY на начало года` |
| тип | `Чистая стоимость` | руб | балансовая стоимость |
| тип | `Total Full PL with Funding` | руб | P&L с начала года |
| тип | `DV01` | руб | DV01 портфеля |
| тип | `Yield` | % | доходность, `14.25` = 14,25 % |
| тип | `Комментарий` | — | текст в `text_value` |
| `Рынок` | `RUONIA` | % | ставка |
| `Рынок` | `RGBI` | пункты | индекс |
| `Рынок` | `RWA` | руб | RWA |

Единицы сумм и Open QTY меняются настройкой «Округление» (например, стоимость
в млрд, P&L в млн) — `axis_4` меняется вместе со значением.

**Дата RUONIA/RGBI/RWA.** Значения, введённые при запуске, пишутся с датой
позиций выпуска (T-1). В тот же файл попадают значения из истории за **другие**
даты, которых ещё нет ни в одном CSV папки результатов (первый выпуск после
появления начального файла отдаёт всю историю).

## Ключ и загрузка

Ключ: `(date_, axis_0, axis_1, axis_2, axis_3)` — уникален по всем файлам.
Грузить день за днём: upsert по ключу.

Повторный прогон за ту же дату пересобирает свой файл целиком. Перед
загрузкой удалите в базе строки этой даты, где `axis_1 <> 'Рынок'`, затем
сделайте upsert по ключу — иначе стёртый в xlsx комментарий останется в базе.
Старые CSV из папки результатов не удаляйте: по ним отчёт понимает, какие
даты рынка уже выгружены.

## Как считать на дашборде

- **Итоги по типу** для `Open QTY`, `Изменение Open QTY`, `Чистая стоимость`,
  `Total Full PL with Funding`, `DV01` — сумма по `axis_1` за дату. Двойного
  счёта нет: у каждого портфеля ровно один тип.
- **Yield по типу** — средневзвешенная, а не сумма и не простое среднее:
  `SUM(Yield × Чистая стоимость) / SUM(Чистая стоимость)` по портфелям типа за
  дату; строки Yield и стоимости одного портфеля сводятся по `(date_, axis_2)`.
  **Портфели с пустым или нулевым Yield в средневзвешенную не входят** — ни в
  числитель, ни в знаменатель: их стоимость занизила бы Yield типа. Так
  выпадают и дополнительные портфели (строки Yield у них нет). Поэтому
  знаменатель берётся только по портфелям, у которых есть ненулевой Yield, а не
  по всей «Чистой стоимости» типа:

  ```sql
  SELECT y.axis_1                                   AS portfolio_type,
         SUM(y.value * v.value) / NULLIF(SUM(v.value), 0) AS yield_wavg
  FROM   <таблица> y
  JOIN   <таблица> v
         ON  v.date_  = y.date_
         AND v.axis_0 = y.axis_0
         AND v.axis_2 = y.axis_2
         AND v.axis_3 = 'Чистая стоимость'
  WHERE  y.axis_0 = 'Портфели'
    AND  y.axis_3 = 'Yield'
    AND  y.value <> 0
    AND  y.date_ = [**date_k]
  GROUP BY y.axis_1
  ```

  Единица «Чистой стоимости» (настройка «Округление») на результат не влияет —
  она сокращается.
- **Среднее RUONIA/RGBI с начала года** — `axis_1 = 'Рынок'`, нужный
  `axis_3`, `date_` от 1 января года выбранной даты по саму дату.
- **Утилизация RWA и DV01** — лимиты заданы в дашборде; фактические значения —
  строки `RWA` и `DV01`.

## Особенности

- Изменение Open QTY считается из одного файла, прошлые выпуски для него не
  нужны: любой выпуск можно пересобрать задним числом. Портфель, купленный в
  этом году, — изменение равно всему Open QTY.
- Портфеля нет в выгрузке — нет и его строк в CSV. Его комментарий не
  теряется: xlsx-витрина хранит его строкой «нет в выгрузке» и вернёт, когда
  портфель появится снова.
- Пустые значения не пишутся вовсе (нет строки — нет значения).
- DV01 или Yield пустые — `python console.py portfolio-report --diagnose
  --input "<файл>"` покажет, нашлись ли колонки, что в них не разобралось как
  число и откуда по каждому портфелю взяты DV01 и Yield.
- Строки ИТОГО в файле нет: итоги считает BI.
- У дополнительного портфеля `Изменение Open QTY` всегда 0, а DV01 и Yield
  нет — в сумму DV01 он не добавляет ничего, из средневзвешенного Yield выпадает.
- Схема та же, что у CSV «Динамики портфелей», — обе можно держать в одной
  таблице, различая по `axis_0`.
