# Структура баланса (План фондирования)

Код: [reports/balance_struct/etl.py](../reports/balance_struct/etl.py).
Команда: `python console.py balance-struct`.

## Источник

Файл `ПФ_дд_мм_гггг.xlsx` из папки `balance_struct_dir` (шаблон —
настройка `balance_struct_regex`).

- Лист **«Прензентация»** (опечатка — часть реального имени листа).
- На листе ищется ячейка-якорь, в тексте которой есть «структура баланса» и
  «млрд». Всё, что выше и левее неё, отбрасывается.
- Колонка якоря — названия статей. Заголовки колонок значений — **даты**: у
  4-й колонки после якоря дата берётся из строки якоря, у остальных — из
  строки под ним. 5-я колонка после якоря выбрасывается, полностью пустые
  колонки тоже.
- Строки «Итого», «МОБ портфель ценных бумаг», «МОБ кредитный портфель»,
  «Резервы по кредитному портфелю МОБ» выбрасываются.
- Каждая статья ищется в справочнике иерархии (ниже). Статьи, которых в нём
  нет, отбрасываются с предупреждением в логе. Одинаковые названия в разных
  ветках (КБ, РБ…) различаются по контексту — по статье-родителю выше.

## Выходной файл

`Навигатор_<имя исходного файла>.csv` (или `Навигатор_combined_<дата>.csv`),
разделитель `,`, UTF-8 с BOM. Несколько дат в одном файле — по одной на
колонку исходной таблицы.

Порядок колонок в файле: `date_, axis_0, axis_1, axis_2, axis_3, value,
axis_4, nversionid` (**`value` стоит перед `axis_4`, колонки `id` нет**).

## Таблица в базе

| Колонка | Тип | Что в ней | Откуда |
|---|---|---|---|
| `date_` | date | дата значения | заголовок колонки значений |
| `axis_0` | text | всегда `План фондирования` | константа |
| `axis_1` | text | `Активы` / `Пассивы` | справочник |
| `axis_2` | text | статья 2-го уровня; пусто у строки `axis_1` | справочник |
| `axis_3` | text | статья 3-го уровня или пусто | справочник |
| `axis_4` | text | статья 4-го уровня или пусто | справочник |
| `value` | int | значение, **млрд руб**, округлено до целых | ячейка таблицы |
| `nversionid` | int | `0` — 1-я и 2-я колонки значений после якоря (в типовом файле C и D), `1` — остальные | позиция колонки |

> **Уточнить:** что означает `nversionid` для дашборда (факт / план?). В коде
> правило перенесено из исходного ноутбука как есть: 0 для двух первых колонок
> значений, 1 для остальных.

Иерархия (`axis_1 → axis_2 → axis_3 → axis_4`):

- **Активы** → Ликвидные активы; ФОР; МБК, Обратное РЕПО; МБК ВГО размещение;
  Портфель ценных бумаг → {Казначейство, БФР, Прочие}; Кредитный портфель
  (гросс) → {КБ, Спец проекты, ОПК, МБ, РБ, ДЧК, ДБП, ДМБ, Прочие клиенты,
  Новые территории}; Резервы по кредитному портфелю; Неработающие и прочие
  активы.
- **Пассивы** → МБК, Лоро, Прямое РЕПО; МБК ВГО привлечение; Клиентское
  привлечение (в т.ч. ЦФА*) → {ДВС → {КБ, Спец проекты, ОПК, МБ, РБ, ДЧК, ДБП,
  ДМБ, Прочие клиенты, Новые территории}, Срочное → {КБ, Спец проекты, ОПК,
  МБ, РБ, ДЧК, ДБП, ДМБ, Прочие клиенты, в т.ч. депозиты ФК, Новые
  территории}, Цифровые финансовые активы}; Средства ГОЗ; Средства
  Минпромторга; Бюджетные средства; Привлечение на финансовых рынках; Прочие
  обязательства; Капитал; Внебаланс; НКЛ; НЧСФ.

Ось статьи определяется глубиной вложенности в справочнике
(`NESTED_BALANCE` в коде): поле `level` там справочное и в расчёте не
участвует.

Строки-родители (например, «Кредитный портфель (гросс)») тоже выгружаются
своими значениями: суммировать все уровни сразу нельзя, будет двойной счёт.
Для итогов берите один уровень: строки, где следующая ось пустая.

## Ключ и загрузка

Ключ: `(date_, axis_1, axis_2, axis_3, axis_4, nversionid)`. Полные дубли
удаляются ещё в ETL, а дубли по ключу пишутся в лог предупреждением.

Один и тот же месяц может прийти в нескольких файлах ПФ (таблица показывает
несколько дат). При загрузке нужен upsert по ключу, а не простая дозапись.

## Особенности

- Пустые значения и строки без даты не выгружаются.
- Единица в файле не подписана (млрд — из текста якоря). Настройка
  «Округление» может перевести значения в другую единицу, и в файле это не
  будет видно.
