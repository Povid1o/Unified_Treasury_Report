# Динамика портфелей

Код: [reports/portfolio_dynamics/](../reports/portfolio_dynamics/) (`etl.py` —
разбор и расчёт, `flat.py` — CSV для BI, `workbook.py` — xlsx).
Команда: `python console.py portfolio-dynamics`. Контракт xlsx — в
[_portfolio_dynamics_spec/CONTRACT.md](../_portfolio_dynamics_spec/CONTRACT.md).

## Источник

**1. Выгрузка «Позиция за период» — два среза: T0 (отчётная дата) и T-7.**
Основной вид — выгрузка **с начала года**:
`Позиция за период  01.01.ГГГГ  -  ДД.ММ.ГГГГ   - SECURITIES.xlsx`, та же, что
у «Отчёта по портфелям». Поэтому достаточно одной выгрузки в день на оба
отчёта: сегодняшняя — T0, недельной давности из архива папок-дат — T-7.
Выгрузка за один день (`ДД.ММ.ГГГГ - ДД.ММ.ГГГГ`) тоже принимается.

Дата среза — **вторая** дата периода из имени файла (или из шапки листа, если
файл переименован). Лежит в папке `portfolio_dynamics_dir` (с папками-датами
`ГГГГ-ММ-ДД`) или в загрузках — отчёт сам находит и раскладывает.

- Лист — тот, где есть колонка «Тип актива».
- Строка «Тип актива» = `Позиция: <КОД>` открывает портфель, строки под ней —
  его бумаги; «Итого / Всего / Total» пропускаются.

| Колонка выгрузки | Что из неё | Как сворачивается в портфель |
|---|---|---|
| Тип актива | код портфеля из `Позиция: <КОД>` | — |
| Чистая стоимость позиции (кон.) | объём портфеля | из строки портфеля; пусто — сумма по бумагам |
| Дюрация | дюрация текущая (на конец периода) | из строки портфеля; пусто — средневзвешенная по стоимости бумаг |
| Duration (нач.) | дюрация на начало периода — **только** у выгрузки за один день, где «Дюрация» пустая | так же |

В выгрузке с начала года колонки «(нач.)» — на 01.01, поэтому ни «Duration
(нач.)», ни «Чистая стоимость позиции (нач.)» «Динамика» из неё не берёт.

Тип портфеля (`HTM`, `HTM_KUAP`, `AFS`, `TSS`) — из справочника `dim_portfolio`
и файла разметки `portfolio_types.json`. Целевая дюрация («Дюрация-КУАП») —
из настройки `portfolio_dynamics_kuap_durations`. Портфели, которых нет в
выгрузке, но объём по ним ведётся руками, — из настройки «Дополнительные
портфели».

**2. «Состояние лимитов на дату ДД_ММ_ГГГГ - Результат.xlsx»** на отчётную
дату: колонки «Тип лимита», «Лимит сверху», «Остаток лимита сверху». Нет файла —
лимиты переносятся из предыдущего выпуска.

**3. Предыдущий выпуск xlsx** — из него переносятся история объёмов по типам,
справочник портфелей, лимиты и комментарии.

## Выходные файлы

- `dinamika_portfeley_<дата T0>.xlsx` — книга схемы v3.0 для людей (витрины,
  светофор, проверки, комментарии). **В BI не грузится.**
- `dinamika_portfeley_<дата T0>.csv` — **для BI**. Разделитель `,`, UTF-8 с BOM.
- `dinamika_portfeley_istoriya_<с>_<по>.csv` — разовая выгрузка истории объёмов
  типов (только по команде `--history-csv`), та же раскладка.

## Таблица в базе (CSV)

| Колонка | Тип | Что в ней |
|---|---|---|
| `id` | int | номер строки в файле, с 0 — не ключ |
| `date_` | date | отчётная дата T0; у строк «Объём типа» — дата из истории |
| `axis_0` | text | всегда `Динамика портфелей` |
| `axis_1` | text | тип портфеля: `HTM`, `HTM_KUAP`, `AFS`, `TSS` |
| `axis_2` | text | код портфеля; **пусто у показателей уровня типа** |
| `axis_3` | text | показатель (таблица ниже) |
| `axis_4` | text | единица: `млрд RUB`, `%`, `лет` или пусто у текста |
| `value` | decimal / пусто | число; у текстовых показателей пусто |
| `text_value` | text / пусто | текст: наименование портфеля, комментарий |
| `nversionid` | text | пусто |

Показатели уровня **портфеля** (`axis_2` = код):

| `axis_3` | `axis_4` | Что | Откуда |
|---|---|---|---|
| `Наименование портфеля` | — | `text_value`; по умолчанию равно коду | `dim_portfolio.portfolio_name` |
| `Объём T0` | млрд RUB | объём на отчётную дату | срез T0, «Чистая стоимость позиции (кон.)» |
| `Объём T-7` | млрд RUB | объём на дату сравнения | срез T-7 |
| `Изменение объёма` | млрд RUB | T0 − T-7 | расчёт; нет, если нет одного из объёмов |
| `Изменение объёма, %` | % | (T0 / T-7 − 1) × 100 | расчёт; нет, если T-7 = 0 |
| `Дюрация текущая` | лет | дюрация на T0 | срез T0, «Дюрация» |
| `Дюрация-КУАП` | лет | целевая дюрация | настройка `portfolio_dynamics_kuap_durations` |
| `Изменение дюрации` | лет | текущая − КУАП | расчёт |
| `Комментарий` | — | `text_value` | жёлтая колонка `view_monitor` в xlsx |

Показатели уровня **типа** (`axis_2` пусто):

| `axis_3` | `axis_4` | Что | Даты |
|---|---|---|---|
| `Объём типа` | млрд RUB | сумма объёмов портфелей типа; **объём `HTM` включает `HTM_KUAP`** | все даты истории, которых ещё нет в CSV папки (см. ниже) |
| `Лимит типа` | млрд RUB | «Лимит сверху» | отчётная дата |
| `Утилизация лимита типа` | млрд RUB | лимит − «Остаток лимита сверху» (по данным системы лимитов) | отчётная дата; нет остатка — нет строки |

## Ключ и загрузка

Ключ: `(date_, axis_0, axis_1, axis_2, axis_3)`.

**История объёмов типов приходит сама.** В ежедневный CSV попадают объёмы
типов за даты, которых в CSV этой папки ещё нет: первый файл — вся история,
дальше — только новая дата (или пропущенные дни). Поэтому файлы можно
дописывать в базу день за днём. Старые CSV из папки результатов не удаляйте:
по ним отчёт понимает, что уже выгружено.

Повторный прогон за ту же дату пересобирает свой файл целиком. Перед
загрузкой удалите в базе строки этой даты уровня портфеля (`axis_2` не пусто),
затем сделайте upsert по ключу: иначе стёртый комментарий останется в базе.

## Особенности

- **Не складывайте «Объём типа» по всем типам:** `HTM` уже содержит
  `HTM_KUAP`. Итог по банку — сумма типов без вложенных.
- Лимит и утилизация пишутся одной строкой на тип, а не в каждой строке
  портфеля — иначе сумма в BI умножила бы лимит на число портфелей.
- Отдельной истории по портфелям нет: объёмы и дюрации портфелей — только на
  отчётную дату каждого выпуска (история копится в базе из ежедневных файлов).
- Единица сумм CSV настраивается отдельно от xlsx («Округление», показатели
  `CSV: …`); `axis_4` меняется вместе со значением.
- Дельта «T0 − T-7» считается только при обоих объёмах: пустой T-7 не
  превращается в ноль (в отличие от формул xlsx).
