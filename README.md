# Unified_Treasury_Report

Единая консоль ETL-отчётов казначейства для BI.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Учётные данные CBonds лежат в `CBonds_API/.env` (`CBONDS_LOGIN`, `CBONDS_PASSWORD`).

Пути к папкам с исходными Excel-файлами и результатами, шаблоны имён файлов и
константы отчётов настраиваются из самой консоли — пункт меню «Настройки»
(см. [раздел ниже](#настройки)). Править [config.py](config.py) руками больше
не нужно.

## Запуск

```bash
python console.py                              # интерактивное меню: выбрать отчёт -> параметры -> запуск
```

Без аргументов запускается интерактивное меню: выбор отчёта из красиво
оформленной таблицы, ввод параметров, спиннер во время загрузки с живыми
логами поверх него. Ctrl+C в любой момент (на выборе отчёта, при вводе
параметров, во время самой загрузки) отменяет только текущую операцию и
возвращает в меню — программа не закрывается.

Каждый отчёт можно запустить и напрямую аргументами командной строки.

## Настройки

Всё, что раньше правилось в `config.py`, теперь задаётся из консоли: пункт
«Настройки» в главном меню или подкоманда `settings`. Изменённые значения
ложатся в `settings.json` рядом с проектом (он в `.gitignore` — у каждого
пользователя свой), значения по умолчанию остаются в коде. Обновление проекта
настройки не затирает.

```bash
python console.py settings --list                        # все настройки и их значения
python console.py settings --list --group portfolio_dynamics   # один раздел
python console.py settings --set jupiter_root="/Volumes/Jupiter"
python console.py settings --set ovp_dir="/Volumes/Jupiter/data/OVP" chpd_dir="..."
python console.py settings --get ovp_dir                 # только значение — удобно в скриптах
python console.py settings --reset ovp_dir               # вернуть значение по умолчанию
python console.py settings --reset-all
python console.py settings --check                       # доступны ли все пути
python console.py settings --path                        # где лежит settings.json
```

Что настраивается: корень сетевого архива, папка логов, папка загрузок, по
каждому отчёту —
папка исходных файлов, папка (или файл) результатов, шаблон имени файла с датой
и формат этой даты; для «Ставок ОФЗ» — путь к `.env`, файл результата и глубина
истории; для «Динамики портфелей» — делитель объёмов, порог расхождения, сдвиг
сравнения по умолчанию, папки по датам и приёмка из загрузок.

**Корень и производные папки.** Пока папка конкретного отчёта не задана явно,
она отсчитывается от корня архива: сменили `jupiter_root` — переехали все
`data/<Отчёт>` и `output/<Отчёт>` сразу. Заданная явно папка от корня больше не
зависит. В интерактивном редакторе «-» вместо значения возвращает настройку к
значению по умолчанию, жёлтым подсвечены изменённые.

**Папки по датам.** Чтобы в папке с исходными файлами не копился «зоопарк»
выгрузок за все даты сразу, отчёт может искать их в подпапках вида `2026-09-18`.
Папки на несколько дней вперёд создаются разом — «д» в редакторе настроек или:

```bash
python console.py settings --make-folders portfolio-dynamics --days 14
python console.py settings --make-folders portfolio-dynamics --days 14 --include-weekends
```

По умолчанию создаются только рабочие дни, начиная с сегодня; повторный запуск
ничего не портит — уже существующие папки не трогаются. Формат имени папки
задаётся настройкой `date_folder_format` («Общее»).

**Проверка путей** (`--check` или «п» в редакторе) показывает по каждому пути,
доступен ли он и сколько файлов в нём нашлось по маске источника. Отсутствие
папки-источника — ошибка (обычно не примонтирован сетевой диск или опечатка);
отсутствие выходной папки — норма, она создастся при первом запуске.

**Некорректные значения не принимаются**: регулярка без ровно одной группы
(иначе отчёт находит файл, но не дату в его имени), формат даты, из которого
дата не разбирается обратно, ноль или отрицательное число там, где нужно
положительное. Несуществующий путь при этом сохраняется с предупреждением —
сетевой диск может быть просто не примонтирован прямо сейчас.

**Логин и пароль CBonds в настройках не хранятся** — они остаются в
`CBonds_API/.env`, закрытом `.gitignore`. Настройкой сделан только путь к этому
файлу: `settings.json` лежит рядом с кодом открытым текстом, и складывать в него
секреты означало бы ухудшить их хранение.

### Ставки ОФЗ (CBonds API)

Три взаимоисключающих режима периода:

```bash
python console.py ofz-rates --date 2026-07-01 --lookback-days 30    # одна дата + история назад (по умолчанию)
python console.py ofz-rates --date-from 2026-06-01 --date-to 2026-06-10   # интервал дат
python console.py ofz-rates --dates 2026-06-01,2026-06-15,2026-07-01      # список конкретных (не обязательно смежных) дат
```

Если корпоративный файрвол не пропускает запросы из Python, тот же отчёт можно
собрать прямо в Excel — запросы уйдут из процесса Excel (нужен Excel под Windows): см.
[excel_ofz/README.md](excel_ofz/README.md).

### Файловые отчёты (ОВП, Структура баланса, ЧПД, NIM, Динамика портфелей)

```bash
python console.py balance-struct --date 2026-06-18            # один файл на дату
python console.py balance-struct --dates 2026-06-18,2026-06-25 --combine   # несколько файлов -> ОДИН csv
python console.py chpd --inputs "a.xlsx" "b.xlsx"              # несколько файлов -> отдельные csv (по умолчанию)
python console.py ovp --inputs report1.xlsx report2.xlsx --combine
python console.py transfert-stavka --short-date 2026-03-17 --long-date 2026-04-30
python console.py portfolio-dynamics --t0-date 2026-09-01 --t7-date 2026-08-25
```

Без `--date`/`--input`/`--inputs`/`--dates` файловые отчёты сами находят
самый свежий файл в папке источника (см. [«Настройки»](#настройки)).

В интерактивном режиме консоль показывает 5-10 последних найденных файлов
(чтобы не засорять экран более старыми) и позволяет выбрать сразу несколько:
номерами из списка, датами (YYYY-MM-DD, в том числе за пределами показанных
5-10) или именами файлов через запятую — можно смешивать. По умолчанию
каждый выбранный файл сохраняется в свой CSV; если выбрано больше одного
файла, консоль спросит, объединить ли всё в один CSV.

У ОВП нет типового имени файла с датой (в отличие от остальных), поэтому его
`SourceConfig` в `config.py` сортирует файлы по дате изменения (mtime), а не
по дате из имени — во всём остальном (топ-N, мультивыбор, batch) работает
так же, как у остальных отчётов.

Если папка из настроек недоступна (не примонтирован сетевой диск,
опечатка в пути) или в ней не нашлось ни одного подходящего файла —
консоль не падает с ошибкой, а предлагает вписать путь(и) к файлу вручную.

«Трансфертные ставки» — особый случай: отчёту нужны ДВА файла за раз
(короткие + длинные ставки), поэтому пакетный режим (несколько запусков за
один вызов) для него пока не реализован.

«Динамика портфелей» — тоже два файла за раз (срез T0 и срез T-7), и ещё две
особенности, которых нет ни у одного другого отчёта.

Во-первых, он отдаёт **.xlsx, а не CSV**: на выходе шаблон обмена схемы v3.0
(см. `_portfolio_dynamics_spec/CONTRACT.md`) — машинные листы `fact_type_daily`
и `fact_portfolio_snapshot`, ручные `dim_portfolio` и `fact_limit`, витрины на
формулах, лист `checks` с 24 проверками и словарь данных `dict`. Имя файла —
`dinamika_portfeley_<дата T0>.xlsx`.

**Раскладка по папкам-датам.** Обе выгрузки за день кладутся в подпапку вида
`2026-09-18` внутри папки исходных файлов — и отчёт **без аргументов** сам
находит нужную: берёт самую свежую папку, *в которой есть файлы* (пустые,
созданные заранее, пропускаются), сам определяет, какой из двух файлов T0, а
какой T-7 — по дате самой выгрузки, а не по имени файла, — и кладёт результат
в `output`. Переименовывать и раскладывать в правильном порядке ничего не нужно.

**Приёмка из загрузок.** Носить файлы руками из «Загрузок» в `data/<дата>/` не
нужно: если в папке нужной даты срезов не хватает, отчёт сам находит их в папке
загрузок (по тому же шаблону имени выгрузки), раскладывает по папкам-датам и
запускается. Посторонние файлы в загрузках не трогаются — только те, чьё имя
подходит под шаблон, и только те два, что нужны на выбранную дату.

При запуске отчёт спрашивает отчётную дату и показывает, на какие даты данные
есть и откуда возьмутся — из папки или из загрузок; Enter выбирает последнюю.

```bash
python console.py portfolio-dynamics                      # последняя доступная дата
python console.py portfolio-dynamics --date 2026-09-18     # конкретная дата (+ приёмка из загрузок)
python console.py portfolio-dynamics --folder 2026-09-18   # конкретная папка (дата, имя или путь)
python console.py portfolio-dynamics --no-import           # не заглядывать в загрузки
```

**Каждый срез кладётся дважды** — в папку отчётной даты (где он нужен как часть
пары) и в папку своей собственной даты. Иначе файл за 11.09, попавший в
`2026-09-18/` как T-7, остался бы в единственном экземпляре, и отчёт на 11.09
потом было бы не собрать без повторной выгрузки. После двух еженедельных
запусков раскладка выглядит так:

```
data/PortfolioDynamics/
├── 2026-09-04/   [04.09]                 ← дубль: сам себе T0
├── 2026-09-11/   [04.09] + [11.09]       ← полная пара
└── 2026-09-18/   [11.09] + [18.09]       ← полная пара
```

Любую из этих дат можно пересобрать задним числом, ничего не выкачивая заново.
Стоит это ровно одного лишнего файла на запуск; выключается настройкой
«Дублировать срез в папку его даты».

Папка загрузок задаётся настройкой `downloads_dir` («Общее», по умолчанию
`~/Downloads`; на русской Windows она может называться «Загрузки»). По умолчанию
файлы **переносятся** — из загрузок исчезают, чтобы те не копили мусор;
настройка «Переносить, а не копировать» переключает на копирование. Ничего не
удаляется ни в том, ни в другом случае. Вся приёмка целиком выключается
настройкой «Забирать выгрузки из загрузок».

Папки создаются заранее пачкой: `python console.py settings --make-folders
portfolio-dynamics --days 14` (или «Настройки» → «д»). Если имя папки и дата
внутри выгрузки разошлись — в лог уйдёт предупреждение, а отчёт будет построен
на дату из выгрузки.

Плоская раскладка (все файлы в одной папке) продолжает работать: её можно
оставить, выключив настройку «Складывать выгрузки в папки по датам», а при
включённой настройке обе раскладки сканируются одновременно — переходить можно
постепенно. Без папок-дат отчёт берёт два самых свежих файла: новее — T0,
предыдущий — T-7.

Во-вторых, он работает **инкрементально: предыдущий выпуск отчёта является
входом для следующего**. Входные выгрузки дают только два среза, а истории
объёмов по типам (лист `fact_type_daily`), лимитов и заметок в них нет — всё
это накапливается в самом файле. Каждый запуск читает предыдущий выпуск
(по умолчанию — самый свежий xlsx в выходной папке, либо явный путь через
`--previous`), дописывает в историю одну дату T0 (повторный прогон за ту же
дату ЗАМЕНЯЕТ свои строки, а не задваивает их), переносит `fact_limit` и
`dim_portfolio` как есть и возвращает `note_text` на место по `portfolio_code`.
Первый запуск, когда предыдущего файла ещё нет, требует явного `--bootstrap`:
история заводится с одной даты, лимиты — нулевые, и их надо заполнить руками.

```bash
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx --previous prev.xlsx
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx --bootstrap
```

Дата отчёта берётся из ВТОРОЙ даты в имени файла выгрузки
(`Позиция за период [01.01.2026] - [01.09.2026] - SECURITIES.xlsx` -> 2026-09-01);
если файл переименовали, та же строка ищется в шапке листа. Объёмы выгрузка
отдаёт в рублях, а схема требует млн RUB — масштаб задаётся константой
`PORTFOLIO_DYNAMICS_VALUE_SCALE` в `config.py`.

## Структура проекта

- `CBonds_API/` — перенесённая библиотека-клиент CBonds JSON API (общая для всех отчётов).
- `common/` — общие утилиты, переиспользуемые разными отчётами:
  - `ui.py` — оформление консоли (rich): меню, спиннер, стилизованные сообщения.
  - `logging_utils.py` — единое логирование (RichHandler в консоль + `logs/<report>.log`).
  - `file_discovery.py` — поиск входных файлов по дате, зашитой в имени файла (топ-N дат / список дат / имя файла, одиночный и множественный выбор).
  - `batch.py` — запуск ETL по списку файлов: раздельные CSV (по умолчанию) или один объединённый (`--combine`).
  - `settings.py` — реестр настроек (значения по умолчанию, разбор и проверка значений) и их хранение в `settings.json`. Без rich и без импорта `config` — его импортирует сам `config`.
  - `settings_ui.py` — пункт меню «Настройки»: экраны редактора и неинтерактивный режим подкоманды `settings`.
- `config.py` — пути к папкам с исходными данными и результатами (`SourceConfig` на каждый источник). Собирается из слоя настроек; руками не правится.
- `settings.json` — изменённые пользователем настройки (создаётся при первой правке, в репозиторий не коммитится).
- `reports/<report_slug>/` — код конкретного отчёта: `etl.py` (получение и преобразование данных) + `report.py` (обёртка для консоли: CLI-аргументы и интерактивный режим).
  - `reports/ofz_rates/` — «Ставки ОФЗ» (кривая доходности ОФЗ из CBonds API).
  - `reports/ovp/` — «ОВП» (конвертация Excel-отчёта «Открытая валютная позиция» в CSV).
  - `reports/balance_struct/` — «Структура баланса» (разбор Excel «ПФ_ДД_ММ_ГГГГ» по иерархии активов/пассивов).
  - `reports/chpd/` — «ЧПД» (разбор Excel «ЧПД YYYY MM DD», лист Table).
  - `reports/nim/` — «NIM» (разбор Excel «NIM_YYYY_MM» по текстовым маркерам).
  - `reports/transfert_stavka/` — «Трансфертные ставки» (два файла: короткие + длинные сроки).
  - `reports/portfolio_dynamics/` — «Динамика портфелей» (два среза выгрузки позиций -> xlsx схемы v3.0; единственный отчёт с xlsx на выходе и инкрементальным накоплением истории). Разбит на три модуля: `etl.py` (разбор выгрузок и слияние с предыдущим выпуском), `workbook.py` (сборка xlsx: листы, формулы, форматирование, валидация, checks), `report.py` (CLI и интерактив), `inbox.py` (поиск выгрузок в папке загрузок и раскладка их по папкам-датам).
- `excel_ofz/` — автономная Excel-версия отчёта «Ставки ОФЗ» (VBA ходит в CBonds API напрямую, без Python).
- `console.py` — точка входа: реестр отчётов + меню/CLI.
- `output/<report_slug>/` — результаты запусков (для файловых отчётов путь берётся из `config.py`).
- `logs/` — логи запусков (по одному файлу на отчёт).

## Добавление нового отчёта

1. Создать `reports/<slug>/etl.py` с получением и преобразованием данных.
2. Если у отчёта есть входные файлы с датой в имени — добавить `SourceConfig` в `config.py` и использовать `common.file_discovery` для поиска файла.
3. Создать `reports/<slug>/report.py` с классом, реализующим `reports.base.Report`.
4. Зарегистрировать отчёт в списке `REPORTS` в `console.py`.
