Добавь в Unified_Treasury_Report новый отчёт «Динамика портфелей»
(slug `portfolio-dynamics`).

- `README.md`, раздел «Добавление нового отчёта» — четыре шага, следуй им.

- `reports/transfert_stavka/` — ближайший аналог: единственный отчёт, которому

- `common/excel_io.py` — читать входные Excel только через него
  (`read_matrix`, `iter_sheet_matrices`): он устойчив к артефактам выгрузок
  из OLAP-кубов и к формулам без закэшированных значений.
- `common/logging_utils.get_logger`, `common/ui`, `common/file_discovery` —
  использовать как во всех остальных отчётах, ничего своего не заводить.

- `_portfolio_dynamics_spec/reference_generator.py` — РАБОЧИЙ эталонный

  и перенеси из него схему, формулы, форматирование, валидацию и проверки.
  Не переписывай схему заново и не «улучшай» её — она согласована.
  Твоя работа: заменить демо-данные на разбор реальных входных файлов и
  встроить генератор в архитектуру проекта.

## 1. Что делает отчёт

На вход — ДВА Excel-файла: срез T0 и срез T-7.
На выход — ОДИН .xlsx по схеме v3.0 из `CONTRACT.md`.

Это первый отчёт в системе, который отдаёт xlsx, а не csv. Всё остальное
(реестр в `console.py`, `SourceConfig` в `config.py`, логирование, спиннер,
Ctrl+C, интерактивный выбор файлов) должно работать ровно как у прочих.

## 2. Откуда берётся какая часть выходного файла

| Лист | Источник |
|---|---|
| `fact_portfolio_snapshot` | `volume_t0` — из файла T0, `volume_t7` — из файла T-7 (join по коду портфеля), дюрации — из файла T0 |
| `fact_type_daily` | строка за сегодня — свёртка T0 по типам; ИСТОРИЯ — из предыдущего выпуска отчёта (см. п. 3) |
| `dim_portfolio` | из предыдущего выпуска; новые коды, встреченные в T0, дописываются с пустым типом и помечаются в логе как требующие ручной привязки |
| `fact_limit` | целиком из предыдущего выпуска — лимиты заводятся руками, скрипт их НЕ трогает |
| `note_text` в срезе | целиком из предыдущего выпуска, merge по `portfolio_code` |
| витрины, `checks`, `dict` | генерируются формулами каждый раз заново |

## 3. Ключевое архитектурное решение: накопление истории

Входные файлы дают только два среза. Ежедневной истории объёмов по типам в
них нет, а она нужна на листе `fact_type_daily` (с 01.01.2026).

Поэтому отчёт работает инкрементально: **предыдущий выпуск отчёта является
входом для следующего**. Алгоритм запуска:

1. Найти предыдущий выпуск (самый свежий xlsx в выходной папке, либо явный
   путь через аргумент `--previous`).
2. Прочитать из него `fact_type_daily`, `dim_portfolio`, `fact_limit`
   и колонку `note_text` из `fact_portfolio_snapshot`.
3. Разобрать входные файлы T0 и T-7.
4. Дописать в `fact_type_daily` строки за дату T0 (по одной на тип).
   Идемпотентность: если строки за эту дату уже есть — ЗАМЕНИТЬ их, не
   продублировать. Историю за прошлые даты не переписывать никогда.
5. Полностью пересобрать `fact_portfolio_snapshot`, вернув `note_text`
   на место по `portfolio_code`.
6. Перенести `dim_portfolio` и `fact_limit` как есть.
7. Записать новый файл, пересчитать формулы не нужно — Excel сделает это
   при открытии; но в тестах значения проверять через LibreOffice/формулы
   не требуется, достаточно проверять входные листы.

Первый запуск (предыдущего выпуска нет): создать файл с одной датой в
истории, пустым `fact_limit` (только строки типов, встреченных в T0, с
нулевыми лимитами) и пустыми `note_text`. В лог — явное предупреждение,
что лимиты надо заполнить руками. Аргумент `--bootstrap` для явного
подтверждения такого запуска.

## 4. Структура кода

```
reports/portfolio_dynamics/
    __init__.py
    etl.py        # разбор входных файлов, слияние с предыдущим выпуском, сборка данных
    workbook.py   # сборка .xlsx: листы, формулы, форматирование, валидация, checks
    report.py     # класс PortfolioDynamicsReport(Report) — CLI и интерактив
```

Разделение `etl.py` / `workbook.py` намеренное: в остальных отчётах ETL
отдаёт DataFrame и `save_report` пишет csv одной строкой, здесь запись —
это сотни строк openpyxl, им не место в ETL.

`etl.py` отдаёт структуру (dataclass или dict of DataFrames) с четырьмя
таблицами: `dim_portfolio`, `fact_limit`, `fact_type_daily`,
`fact_portfolio_snapshot`. `workbook.py` принимает её и пишет файл.

Ошибки — своим классом `PortfolioDynamicsError(RuntimeError)`, как
`TransfertStavkaError`. `PermissionError` при записи (файл открыт в Excel)
перехватывать с понятным сообщением — как в `transfert_stavka/etl.py`.

    filename_regex=...,   # ЗАПОЛНИТЬ по реальным именам файлов

)

Если у файлов нет даты в имени — сделай как у ОВП: без `filename_regex`,
сортировка по mtime.

## 6. CLI

```bash
python console.py portfolio-dynamics --t0-date 2026-09-01 --t7-date 2026-08-25
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx --previous prev.xlsx
python console.py portfolio-dynamics --t0-input a.xlsx --t7-input b.xlsx --bootstrap
```

Аргументы: `--t0-date`, `--t7-date`, `--t0-input`, `--t7-input`,
`--previous`, `--bootstrap`, `--output`.
По умолчанию — самые свежие файлы из источников, как у остальных отчётов.

Интерактивный режим: два `file_discovery.prompt_for_file` подряд с
заголовками «Срез на сегодня (T0)» и «Срез на T-7», как в
`transfert_stavka/report.py`.

Зарегистрируй `PortfolioDynamicsReport()` в `REPORTS` в `console.py`.

Имя выходного файла: `dinamika_portfeley_<дата T0>.xlsx`.

## 7. Структура входных файлов

Оба файла (T0 и T-7) — выгрузка одного и того же вида, иерархическая.
Нужны ровно четыре колонки:

| Колонка в файле | Что это |
|---|---|
| `Тип актива` | либо маркер портфеля, либо наименование бумаги (см. ниже) |
| `Чистая стоимость позиции (кон.)` | объём позиции |
| `Duration (нач.)` | дюрация на начало периода |
| `Дюрация` | дюрация на конец периода |

Остальные колонки игнорировать.

### Иерархия задана значениями внутри колонки «Тип актива»

Строка, значение которой начинается с `Позиция: ` — это ЗАГОЛОВОК ПОРТФЕЛЯ.
Текст после `Позиция: ` — код портфеля: `AFS_TR_RUR`, `HTM_LINKERS_SEC`,
`HTM_ALCO` и т.п. Все последующие строки — бумаги внутри этого портфеля,
вплоть до следующей строки `Позиция: ...`, которая открывает новый портфель.

Алгоритм разбора:

1. Идти по строкам сверху вниз, держать «текущий портфель».
2. Строка вида `Позиция: <CODE>` — запомнить `<CODE>` как текущий портфель
   (обрезать пробелы; допускать `Позиция:<CODE>` без пробела и разное
   количество пробелов; сравнение через `excel_io.normalize_label`).
3. Любая другая непустая строка — бумага текущего портфеля.
4. Строки до первого `Позиция: ...` — шапка выгрузки, отбросить.
5. Строки, у которых текущего портфеля нет, в данные не попадают —
   посчитать их и написать количество в лог.

### Агрегация до портфеля

- `volume_t0` (и `volume_t7`) = СУММА `Чистая стоимость позиции (кон.)`
  по бумагам портфеля.
- Дюрация портфеля = СРЕДНЕВЗВЕШЕННАЯ по `Чистая стоимость позиции (кон.)`,
  а НЕ сумма и не простое среднее:
  `sum(duration_i * value_i) / sum(value_i)`.
  Если сумма весов равна нулю — оставить пусто, не делить на ноль.
- Бумаги с пустой дюрацией исключать из расчёта весов, но НЕ из суммы объёма.

Если в самой строке `Позиция: ...` числовые колонки заполнены (выгрузка
даёт подытоги), брать значения оттуда, а посчитанные по бумагам использовать
для сверки: расхождение больше 0.5% — предупреждение в лог с названием
портфеля и обоими числами. Если строка пустая — считать по бумагам.

### Маппинг на схему выходного файла

| Из файла | В `fact_portfolio_snapshot` |
|---|---|
| код из `Позиция: ...` | `portfolio_code` |
| `Чистая стоимость позиции (кон.)`, файл T0 | `volume_t0` |
| `Чистая стоимость позиции (кон.)`, файл T-7 | `volume_t7` |
| `Duration (нач.)`, файл T0 | `duration_current_yrs` |
| `Дюрация` (конечная), файл T0 | `duration_target_yrs` |

Да, имена `current` / `target` не совпадают по смыслу с «нач.» / «кон.» —
это осознанное решение, схему не менять и колонки не переименовывать.
Маппинг выше соблюдать буквально.

Из файла T-7 берётся ТОЛЬКО объём. Дюрации оттуда не нужны.

`portfolio_type` в выгрузке отсутствует — он берётся из `dim_portfolio` по
коду. Для кода, которого в справочнике ещё нет: завести строку с типом,
угаданным по префиксу кода до первого `_` (`AFS_TR_RUR` -> `AFS`,
`HTM_ALCO` -> `HTM`), только если такой тип уже есть в `fact_limit`; иначе
оставить тип пустым. В обоих случаях — предупреждение в лог со списком
новых кодов: их привязку человек подтверждает руками.

### Единицы измерения

Схема предполагает млн RUB. Выяснить, в каких единицах приходит
`Чистая стоимость позиции (кон.)`, и при необходимости поделить на 1e6 —
константу масштаба вынести в `config.py`, не хардкодить в парсере.

### Что ещё ожидать в выгрузке

- числа как текст с пробелами-разделителями и запятой вместо точки;
- объединённые ячейки в шапке (`excel_io.read_matrix` их разворачивает);
- строки «Итого» / «Всего» вне иерархии — отбрасывать, они не бумаги;
- лишние листы: нужный лист искать по наличию колонки `Тип актива`,
  а не по индексу.

Прежде чем писать парсер, попроси у меня по одному примеру файла T0 и T-7,
разбери их через `common.excel_io.read_matrix` и покажи: на какой строке
шапка, какие индексы у четырёх нужных колонок, сколько нашлось портфелей и
бумаг, в каких единицах объёмы. Только после этого пиши код.

## 8. Требования к выходному файлу

Всё уже реализовано в `reference_generator.py`, повтори оттуда:

- строка 1 каждого листа — технические заголовки snake_case;
- умные таблицы Excel на каждом листе с данными;
- формулы только уровня Excel 2007 (SUMIFS, COUNTIFS, INDEX, MATCH,
  IFERROR, SUMPRODUCT) — никаких XLOOKUP/FILTER/UNIQUE;
- именованные диапазоны BUSINESS_DATE, LOOKBACK_DAYS, PORTFOLIO_CODES,
  PORTFOLIO_TYPES;
- цветовая маркировка: синяя шапка — пишет код, жёлтая — только человек
  (`dim_portfolio`, `fact_limit`, колонка `note_text`), зелёная — витрины;
  витрины защищены от правки кроме B3 и D3;
- лист `checks` с 24 проверками, статусы OK/FAIL;
- шрифт Arial, форматы: суммы `#,##0`, проценты долями `0.0%`,
  дюрация `0.00`, даты `YYYY-MM-DD`.

Логируй в `logs/portfolio_dynamics.log`: сколько строк истории перенесено,
сколько дописано, сколько заметок сохранено, сколько новых портфелей
встречено, и итог по листу `checks` (сколько FAIL).

## 9. Тесты

По образцу `tests/test_ovp_etl.py`:

1. Слияние `note_text`: прогон поверх файла с заметками их сохраняет.
2. Идемпотентность: два прогона за одну дату T0 не дублируют строки в
   `fact_type_daily`.
3. История: строки за прошлые даты не изменились после прогона.
4. Сверка грейнов: сумма `volume_t0` по типу совпадает с `volume_amount`
   этого типа за дату T0 в пределах 0.5%.
5. Новый портфель в T0 попадает в `dim_portfolio` и логируется.
6. Разбор иерархии: на синтетическом листе с двумя блоками `Позиция: ...`
   бумаги распределяются по своим портфелям, шапка до первого маркера
   отброшена, строка «Итого» не попала в данные.
7. Средневзвешенная дюрация: портфель из двух бумаг с разными объёмами даёт
   дюрацию, взвешенную по стоимости, а не среднее арифметическое.

## 10. Критерии приёмки

1. `python console.py` показывает «Динамика портфелей» в меню.
2. Отчёт запускается и из меню, и аргументами; Ctrl+C отменяет только его.
3. Выходной файл открывается в Excel без ошибок формул.
4. `pd.read_excel(path, sheet_name="fact_type_daily")` читается без аргументов.
5. Повторный прогон сохраняет заметки и не ломает историю.
6. README дополнен: отчёт в списке и в разделе про файловые отчёты, с
   оговоркой, что он отдаёт xlsx и работает инкрементально.
