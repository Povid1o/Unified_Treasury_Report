# Отчёт «Ставки ОФЗ» в Excel

Автономная книга с макросами: сама ходит в CBonds API и кладёт выгрузку на лист
«Отчёт» — без Python. Нужна там, где корпоративный файрвол пропускает запросы
Excel, но гасит `python`/`requests`.

Запросы уходят из процесса Excel через `MSXML2.XMLHTTP` (стек WinINET) — то же
самое, чем пользуются встроенные веб-запросы Excel, с системными настройками
прокси и аутентификации. Если он не создастся, модуль по очереди пробует
`MSXML2.ServerXMLHTTP`, `WinHttp.WinHttpRequest` и пишет в лог, какой транспорт
сработал.

## Где что работает

| | Сборка книги | Запуск отчёта |
|---|---|---|
| **macOS / Linux** | да, `python excel_ofz/build_workbook.py` | **нет** |
| **Windows + Excel** | да | да |

Запускать книгу можно только в Excel под Windows. HTTP-запрос и разбор ответа
держатся на COM-объектах (`MSXML2`/`WinHttp`, `ADODB.Stream`,
`Scripting.Dictionary`), а в Excel для macOS COM нет вообще — там книга
открывается и редактируется, но кнопки сразу скажут, что запуск невозможен.
На Mac для этого есть обычная Python-версия: `python console.py ofz-rates`.

## Сборка

```bash
python excel_ofz/build_workbook.py
```

Собирает `excel_ofz/dist/ОФЗ_ставки.xlsm` целиком: листы, именованные
диапазоны, справочник индексов, вшитый модуль VBA и кнопки. Ни Excel, ни
Windows для сборки не нужны — проект VBA (`vbaProject.bin`) генерируется на
Python по спецификациям [MS-OVBA] и [MS-CFB], см. `vba_container.py`.

Пересборка перезаписывает файл в `dist/` — **логин и пароль, вписанные в книгу,
при этом теряются**. Рабочую копию держите вне `dist/`.

Справочник индексов, список сроков, глубина истории и таблица «Пропуски»
импортируются из `reports/ofz_rates/etl.py` и `CBonds_API/`, поэтому
Excel-версия не разъезжается с Python-версией при правках.

Если проект VBA почему-то не подхватится, рядом лежит `ofz_report_cp1251.bas`
для ручного импорта (`Alt+F11` → `File → Import File…`).

## Что внутри книги

| Лист | Назначение |
|---|---|
| **Параметры** | Логин/пароль, период, сроки кривой, пути выгрузки, кнопки |
| **Отчёт** | Сырая выгрузка под BI, без оформления (см. ниже) |
| **Лог** | Ход выполнения: что запрошено, что получено, что пропущено и почему |
| **Индексы** | Справочник `type_id` CBonds (39 индексов). VBA берёт ID отсюда — новый индекс добавляется строкой, без правки кода |
| **Пропуски** | Показатели, которых нет ни в одном доступном аккаунту эндпоинте; на каждом запуске уходят в лог предупреждением |

### Лист «Отчёт»

Это не отчёт для человека, а ровно то, что писал `save_report()` в CSV: строка
заголовка `date_, name_group, name_st, unit, type_val, fvalue` и строки данных.
Никаких заливок, объединённых ячеек, итогов, закреплённых областей и подписей —
лист рассчитан на загрузку в BI как есть.

Единственный формат на листе не косметический: колонка `date_` объявлена
текстовой, иначе Excel распознает `2026-07-01` как дату и подставит локальный
формат вместо ISO. `fvalue` намеренно оставлен в General — в ячейке лежит то же
число, что ушло бы в CSV (`13.5`, а не `13.50`).

Отдавать в BI саму рабочую книгу не стоит: в ней лежат логин и служебные листы.
Для этого есть две кнопки — **Выгрузить XLSX** (отдельный файл с единственным
листом `ofz_report`) и **Выгрузить CSV** (UTF-8 с BOM, байт в байт как у
Python-версии).

## Первый запуск

1. На листе «Параметры» заполнить **Логин**. Пароль лучше оставить пустым —
   тогда он спрашивается при каждом запуске и не сохраняется в файле.
2. Нажать **Проверить связь** — это и есть проверка, проходит ли Excel через
   файрвол. В сообщении будет HTTP-статус и название сработавшего транспорта.
3. Выбрать режим периода и нажать **Сформировать отчёт**.

При первом открытии Excel спросит про макросы — их нужно разрешить.

## Параметры

| Ячейка (имя) | Что задаёт |
|---|---|
| `p_login`, `p_password` | Учётные данные CBonds (`CBONDS_LOGIN` / `CBONDS_PASSWORD`) |
| `p_mode` | `1` — дата + история назад, `2` — интервал, `3` — список дат |
| `p_date`, `p_lookback` | Режим 1: дата отчёта (пусто = сегодня) и глубина в календарных днях |
| `p_date_from`, `p_date_to` | Режим 2: границы интервала |
| `p_dates` | Режим 3: `2026-06-01,2026-06-15,2026-07-01` — даты не обязаны идти подряд |
| `p_tenors` | Сроки кривой через запятую |
| `p_limit` | Лимит записей на один срок за запрос |
| `p_xlsx_path`, `p_csv_path` | Куда пишут кнопки выгрузки (пусто = рядом с книгой) |

Даты — строками `YYYY-MM-DD`. Ячейки отформатированы как текст, чтобы Excel не
переводил их в локальный формат.

## Соответствие Python-версии

Перенесено один в один с `reports/ofz_rates/etl.py`:

- эндпоинт `get_index_value_new`, фильтры `type_id`/`date ge`/`date le`,
  сортировка по дате по убыванию, тот же формат payload;
- три режима периода с тем же приоритетом; в режиме 3 запрашивается диапазон
  `[min; max]` одним запросом на срок и результат фильтруется по списку дат;
- предупреждение, если период длиннее 100 дней (глубина архива демо-подписки);
- обработка HTTP 301/403/500/504 теми же сообщениями;
- валидация: формат даты `YYYY-MM-DD`, `type_val = "Значение"`, числовой
  `fvalue` с округлением до 2 знаков, дедупликация по
  `(date_, name_group, name_st)` с сохранением последнего значения, сортировка
  по `name_group, name_st, date_`;
- ошибка по одному сроку не валит весь отчёт — пишется в лог, срок пропускается;
- отсутствующий индекс пропускается с предупреждением. Это касается и `6Y` из
  списка по умолчанию: у CBonds нет `RUB_Yield_Curve_6Y`, поэтому и Python, и
  Excel-версия его штатно пропускают — список сроков оставлен как в
  `OFZ_YIELD_TENORS`;
- CSV пишется в UTF-8 с BOM, как `to_csv(encoding="utf-8-sig")`.

Отличие: Python пишет лог в `logs/ofz_rates.log` с накоплением, Excel — на лист
«Лог», очищая его в начале каждого запуска.

## Если связи нет

Кнопка «Проверить связь» показывает, на чём именно всё встало:

- **транспортная ошибка** (таймаут, отказ соединения, ошибка сертификата) —
  запрос гасит прокси/файрвол; нужно разрешить HTTPS к `ws.cbonds.info`;
- **HTTP 403** — дошли до CBonds, но не приняли логин/пароль либо нет доступа к
  операции;
- **HTTP 500** — доступ к эндпоинту не выдан подписке.

## Файлы

- `ofz_report.bas` — модуль VBA (исходник, UTF-8): HTTP, JSON-парсер, сборка и
  валидация отчёта, выгрузки.
- `vba_container.py` — генератор `vbaProject.bin`: сжатие [MS-OVBA] и
  контейнер OLE [MS-CFB].
- `xlsm_package.py` — досборка пакета OOXML: вшивание проекта VBA и кнопок.
- `build_workbook.py` — точка входа сборки.
- `dist/` — результат сборки (в git не хранится).
